# 01 产品需求与范围

## 产品定位
面向学生的升学决策支持与执行工作台：依据官方资料说明有哪些可考虑的路线、哪些条件尚未满足、有哪些数据仍不确定，并将学生确认的目标转成申请与学习任务。系统辅助决策，不替学生选择唯一人生路线，不承诺录取，不作为学校招生录取决策系统。

## 第一版范围
国内一个生源省份普通高考本科；海外英国本科。先用国内5所、英国5所高校的约20—40条招生单元/年度记录验证流程，后续扩展依据是数据覆盖与审核能力，而不是宣传中的学校数量。省份通过配置选择，其他省份在界面中明确显示“尚未支持”。

本科、硕士、博士、专升本、转学不能共用一套字段与硬规则。其他国家、本科特殊招生、预科与衔接项目可先提供带来源的说明卡，但在完成独立适配器和测试前不生成个性化资格结论。预科说明不得暗示保证升入某个大学或专业。

按申请周期保存资料，不固定使用“今年招生”。2026年看到的2027入学要求可用于2027申请；2026录取结果是历史资料，不能自动成为2027门槛。

## 最小闭环
学生补充资料并确认 → 检查缺失项 → 读取适用年度与身份的招生事实 → 资格规则核验 → 候选路线比较 → 差距和待核验项 → 用户确认目标 → 生成可执行任务 → 新成绩或招生信息变化后给出修订建议。

## 三个用户角色
学生：管理个人资料与方案，确认学习/申请任务，决定是否共享。
被授权的顾问或监护人：仅访问明确授权的学生与字段；监护人与顾问并不自动拥有所有会话权限，按年龄、适用规则与有效授权设计。
数据管理员：审核公开招生资料、规则和发布版本；不默认访问学生私有资料。

## 学生画像
先采用结构化表单，聊天仅用于解释问题和补充信息。模型提出的画像改动必须让学生确认再保存版本。

必要项按路线逐步询问：学段、课程体系、预计毕业与入学年、考试省份和科类/选科、成绩及满分与来源、成绩是实得还是预测、专业兴趣、地区偏好、预算范围和币种、每周可安排时数。国际路线另问用于资格判断的申请身份和课程资格，不要求身份证/护照号码。

特长记录成有证据的经历：项目/竞赛名称、主办方、时间、级别、本人角色、作品或证书、学生自述与已核验状态。兴趣不是已达成资格；获奖不是通用加分。没有明确官方依据时只用于兴趣匹配和材料准备。

模型不得通过姓名、照片、口音或兴趣推断民族、宗教、健康、智力、家庭社会阶层等属性。预算由学生主动选择，不能推断家庭收入。专业体检等特殊限制只在相关时显示官方核验项，涉及健康的细节应最小化并由人工确认。

## 功能范围
### A 资料问答
回答招生条件、材料、计划和日期。每条关键事实展示来源、适用年度、原文片段与复核状态。无法支持的内容明确留空。通用学习建议与官方招生事实使用不同的视觉标签。

### B 院校/项目比较
比较单位是具体招生机会，不是大学品牌。显示课程、学位、校区、入学年、申请渠道、条件、费用口径、材料、截止日期、未知项。学校排名仅能作为用户可选参考，不是默认适配度。

### C 路线规划
同时展示当前可考虑、有官方后补路径、明确不满足、待核验四类状态。保留替代路线及取舍，不强制合并国内外为一个总分榜。不输出未经校准的录取概率。

### D 学习与申请计划
从学生确认的目标反推任务。区分学校固定期限、考试/材料准备、自主学习目标。每项任务必须有目标、所需时间估计、验收条件、前置依赖与用户确认状态。估时属于可修改的计划参数，不是教育效果保证。

### E 变化提醒
检测到官方页面变化后先进入审核；发布新证据后标记受影响方案needs_review。给学生展示改变了哪项条件、影响哪些项目、哪些任务需要调整。旧版方案可查看；已完成任务不被覆盖。

### F 管理后台
登记来源、原文/抽取结果并排核验、处理冲突、发布规则版本、查看数据覆盖与陈旧度、撤回错误记录。MVP必须有，不推迟到商业化以后。

## 页面建议
学生资料；项目查询/比较；路线与差距；学习/申请时间线；带证据的问答；数据审核后台。主页用项目卡片和任务卡片，而不是只有聊天框。支持表格筛选、原文定位、日期类型标签、修订前后对照。

## 明确不做
全网无限爬取；所有国家所有学段；从少量历史分数估算精准录取概率；无依据的学历/GPA换算；替用户提交申请或付款；伪造经历与申请材料；一开始自建模型/微调/复杂多智能体；高成本自动题库与完整学科诊断系统。

## 成功定义
一个人能使用合成画像完成资料确认—项目比较—依据核验—确认计划—观察变更影响；关键错误会被规则与状态机拦截；开发者能展示真实测试记录、数据审查过程与已知局限。上线前必须另行完成真实数据质量、专业适用性与个人信息评审。
