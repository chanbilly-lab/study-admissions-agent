## 2. 目标用户与权限

| 用户 | 主要需求 | 权限边界 |
| --- | --- | --- |
| 未登录访客 | 查询已发布项目、条件和公开证据 | 不创建或读取私有画像；公开覆盖范围和更新时间 |
| 学生 | 确认资料、比较资格、查看依据、确认和跟踪计划 | 仅自己的资料和授权范围；自己决定目标 |
| 被授权顾问/监护人 | 在授权范围内辅助核验与复盘 | 必须有显式、可撤回授权；角色不自动获得学生资料 |
| 数据管理员/审核者 | 登记来源、导入、核验、发布或撤回事实 | 默认不能查看学生画像；关键发布有审核记录 |
| 运营人员 | 监控服务、响应错误和删除请求 | 使用最小权限及审计；无普遍私有数据访问权 |

目标用户所在地为中国大陆及香港、澳门、台湾，计划在中国大陆部署；方向为高中升本科。产品年龄政策已明确、未成年私有关闭；正式主体/告知及法律适用性仍待落实。年龄流程必须先形成政策再实现；未知年龄或缺少必要授权时不开放私有画像处理，不默认按成人放行。

## 3. 核心使用场景

1. 学生查询配置省份普通高考本科或英国本科项目，看到适用年度、课程、身份、要求和证据；无记录的范围显示数据缺口。
2. 学生登录，了解资料处理用途并完成必要流程，逐步填写资料，显式确认保存新画像版本。聊天建议不能直接修改画像。
3. 学生选择项目，系统按申请阶段和范围计算四态；逐条显示成绩、条件、缺失项、规则版本和引用。
4. 学生比较资格、历史竞争背景、偏好与数据质量。没有数据的维度明确未知，不混成一个录取概率或总分。
5. 学生确认目标后生成计划草案，查看期限、估时、验收标准与容量冲突，再显式确认计划。
6. 学生记录任务完成或新成绩；发布的新证据触发 needs_review 和修订草案，旧计划和已完成记录保留。
7. 管理员人工导入授权使用的招生材料，核验数值、年度、身份和定位，发布不可变版本；错误记录能撤回并追踪影响。
8. 学生撤销顾问授权、导出或申请删除资料；系统处理数据库、附件、缓存和备份留存，显示进度。
9. 访客查全国不同地区/年度的分数线与历史投档/录取，区分考试口径和专业组；看专业入学届培养及实际毕业人群统计，无法比较或未采集时明确说明。

原规格 M2 的采集部分延期；本次公众 MVP 以人工导入、人工复查和变更发布覆盖数据更新。保留 M2 历史编号，不把延期功能当已实现或首版开发许可。其他原里程碑作为能力主题，实际工作以 [Task 列表](tasks.md) 为单位；认证与运行保障贯穿上线准备，不等到最后才补。

## 6. 核心数据与业务规则

### 资格四态

| 状态 | 定义 | 必须展示 |
| --- | --- | --- |
| eligible | 在指定阶段、范围与版本内，完整必需表达式为真 | 已满足条件、依据；不表示被录取 |
| ineligible | 明确适用的完整必需表达式为假，且无适用政策允许该失败后补 | 条件、实得输入、依据、可核验的替代信息 |
| conditional | 有适用、已审核、带期限的后补/后续满足政策 | 尚欠条件、政策证据、期限证据、阶段 |
| unknown | 关键输入或有效规则/证据缺失、冲突、过期或不可核验 | 缺失原因、需要补充或人工处理的项目 |

先校验适用范围，再按 all/any/not 完整表达式计算三值，不能只统计原子失败或缺失数。例如 any(true,false) 和 any(true,unknown) 为真，all(false,unknown) 为假，not(unknown) 仍未知；未选中的可替代分支不阻挡已满足的路线。完整必需表达式的明确硬失败优先；剩余必要未知若无适用后补政策仍为 unknown；仅有已获有效政策支持的待满足义务时为 conditional；完整条件为真且无必要后补义务才 eligible。后补不能把任意未知或 not 分支直接变真。范围不适用时返回 unknown/unsupported，不能使用其他年度规则评估。不存在适用后补依据的必要缺成绩必须 unknown。

实得与预测分别存；满分与单位不匹配不自动换算。兴趣、预算和普通特长不是招生硬资格；历史最低分不是当前门槛或录取概率。规则声明式、类型受限，发布前人工审核，模型只做受约束的说明。

### 日期与计划

申请、平等审理、补材料、语言后补、奖学金、接受 offer 日期分事件保存。原文只含日期时不补 23:59；时区使用地区标识，只有可唯一换算时保存 UTC 瞬时。过平等审理日不自动等于完全不能申请。

官方固定期限、学生目标日期与内部安排分开。估时是可调整参数；无测评证据不诊断知识薄弱点。超容量报告冲突；新成绩或规则变更只产生修订建议，不静默覆盖确认计划。

### 数据与模型模式

未来配置分离 `data_mode=demo/verified` 与 `model_mode=disabled/mock/live`。mock 只在 demo 环境；verified + disabled 使用真实发布事实和确定性模板。现有 M0 /v1 仍是 demo + mock/live，占位 live 不可用，未实现新配置。

## 7. 非功能需求与上线门槛

- **准确性**：关键事实具备项目/年份/身份/路径范围、版本、定位与审核；无证据明确未知；严重误放行、越权和确定性截止换算错误在固定回归集中为 0。
- **授权**：所有私有列表、对象、附件、导出、缓存与异步任务经过服务端授权；数据管理员不能因角色读取学生私有档案。
- **安全**：标准身份协议、会话撤销、CSRF/对象授权、上传隔离、秘密管理与恢复演练有专项检查；外部原文是数据，不是指令。
- **可维护性**：模块化单体、可替换 provider/storage；迁移有回滚或向前恢复方案；没有需求就不引入队列或微服务。
- **可用性**：移动/桌面主流程、键盘操作、错误/加载/空状态；模型关闭或故障不损坏确定性核心。
- **运行**：SLO、流量/容量、成本上限、数据留存、RPO/RTO 由负责人确认后进入部署验收，不虚构达到的性能。
- **质量**：离线单元/契约测试、PostgreSQL 集成、关键端到端、授权与删除/恢复测试、独立招生领域抽查；报告实际分母、命令与失败。

首个公众版本不等于可以省略安全与隐私。正式服务需要确认用户地域、供应商、年龄与处理规则；本规划不能代替具体合规判断。若涉及中国用户，应核验包括必要性、透明度、删除、未成年和跨境在内的适用义务。不满 14 周岁个人信息与监护人同意有专门规定；14–17 岁流程也需独立决定。[个人信息保护法官方文本](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

中国大陆公众部署还须按实际经营方式确认互联网信息服务备案/许可及相关服务要求；若启用面向公众的生成式功能，另核验适用规则及服务商责任。由负责人完成适用性审查和手续记录后才允许发布，不把采购供应商或部署成功等同于完成这些要求。[非经营性互联网信息服务备案管理办法](https://www.miit.gov.cn/zcfg/xxtxl/art/2024/art_7e48434c08c24131b4b7eecfca5b2b6c.html)、[生成式人工智能服务管理暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898326795531.htm)
