## ADR-062 · 私有历史与公开源码分离

- **Decision ID／日期／状态**：ADR-062／2026-10-14／用户明确确认并已实施。
- **背景**：用户新要求修复隐私后公开源码；原全部分支历史元数据含私人邮箱，仅改最新HEAD无法去除。原规则禁止擅自强推／改写已发布历史。
- **决策**：原ID1400234431改名study-admissions-agent-private-archive并保持PRIVATE／只读归档；以已审最新源码及noreply新历史建立同名PUBLIC库ID1418914840，默认codex/privacy-release。原checkout／镜像保留并指备份，公开开发用D:/Projects/study-public。

- **替代方案**：改写全部refs需要更广具体授权，并可能留下平台缓存旧对象；只改HEAD不能满足历史隐私。
- **影响**：仅Git源码发布与工作副本管理；API／DB／架构／依赖／代码／业务门槛不变。实际私有上传核对后已公开，原工作及历史未丢失，没有强推；应用检查／CI／部署未执行。最新公开授权替代旧源码必须私有规则，不替代真实业务门槛。详见source_publication.md。

记录日期：2026-10-01，Asia/Hong_Kong。重要架构、数据库、API、框架/依赖、技术/部署或后续实施决定在此记录；普通代码修改不写 ADR。每条必须含 Decision ID、日期、背景、决策、原因、考虑过的替代方案、影响，并补充状态及来源。后续变更以新 ID 引用被替代的记录，保留历史。

## ADR-004 · 确定性四态与证据日期边界

- **Decision ID**：ADR-004。
- **日期**：2026-10-01（补录）；原单项决定日期未独立记录。
- **状态**：M0 已有四态与受限原子规则；完整表达式/路径/日期模型为规划。
- **背景**：缺成绩、替代资格和后补政策不能由模型猜测。
- **决策**：规则不调用模型或执行 eval/exec；结果 eligible/ineligible/conditional/unknown。完整 all/any/not 表达式归约，必要缺成绩无适用、已审核、带期限的后补证据时 unknown。日期精度保留，不造 23:59 或时区瞬时。
- **原因**：依据不足、跨范围或分支真值错误会导致误放行/误淘汰；数值和日期需可重放。
- **考虑过的替代方案**：本次对照为模型直接判断资格、所有缺分默认后补、原子失败计数；无法提供确定性边界。
- **影响**：T25–T28 与日期任务验收真值表、后补范围和参考日历；eligible 不表示录取，不输出录取概率。
- **来源**：[requirements](requirements.md)、[database](database.md)、[api](api.md)。

## ADR-005 · 数据模式和模型模式独立

- **Decision ID**：ADR-005。
- **日期**：2026-10-01（补录）；原单项决定日期未独立记录。
- **状态**：公众模式规划；M0 仍只有 demo＋mock/live 占位，live 不可用。
- **背景**：正式资格和计划应能无模型密钥运行，合成解释不能冒充真实服务。
- **决策**：拟 data_mode=demo/verified 与 model_mode=disabled/mock/live 分开；mock 仅演示，verified＋disabled 用真实发布事实和模板。live 失败明确报错，不静默换模式；模型只解释经校验内容。
- **原因**：将业务正确性与供应商可用性分开，保留可替换接口与明确失败。
- **考虑过的替代方案**：本次对照为统一 demo_mode 或 live 故障自动返回 mock；会混淆真实依据和调用状态。
- **影响**：T03 与条件启用 T37–T39；供应商、地域、预算和数据流仍待 D05，未获启用授权。
- **来源**：[architecture](architecture.md)、[requirements](requirements.md)。

- **状态**：采纳的公众规划；真实审核发布、事件/删除作业未实现。
- **背景**：真实招生要求需审核，资料变化和删除恢复不能依赖临时任务或旧备份状态。

## ADR-007 · 正式认证、资源授权与私有存储

- **Decision ID**：ADR-007。
- **日期**：2026-10-01（补录）；原单项决定日期未独立记录。
- **状态**：采纳的架构建议；正式身份/存储供应商及公众流程未实施。
- **背景**：DEMO token 不能承载真实学生数据，数据管理员也不应默认读取私有画像。
- **决策**：拟 OIDC 授权码＋PKCE，由 FastAPI BFF 建立服务端会话；同源 HTTPS、Secure/HttpOnly Cookie、CSRF；owner＋显式字段/动作/期限 grant，不预建 SaaS 多租户。文件通过可替换私有 Storage 与逐次授权访问。
- **原因**：使用标准认证协议，减少浏览器 token 暴露，授权贯穿 API/缓存/作业/导出；保留供应商选择余地。
- **考虑过的替代方案**：本次对照为自建密码、SPA 长期 token 存 localStorage、只用前端守卫或默认公开文件；增加身份或泄露风险。SPA＋PKCE 仍是需另行评审的备选。
- **影响**：T04–T10/T14 等落实协议与准入；D01/D02/D04/D06 仍待决定。监护同意不等于全部资料访问，拒绝可选模型不应失去确定性核心。
- **来源**：[architecture](architecture.md)、[api](api.md)。

- **原因**：现阶段只有metadata，精确可测授权能接入后续domain而不提前暴露学生资料；normalized SQL EXISTS可在PG/SQLite可靠限制字段和计数；独立接受防任意UUID立即生效；版本/revision防旧确认重放恢复授权。
- **考虑过的替代方案**：自动按advisor/guardian角色共享全部资料（越权）；客户端任意UUID即active（缺独立主体接受）；JSON.contains过滤scope（两数据库语义不同）；直接在T07owner接口里放宽（影响现有边界）；提前共享未实现的domain/整文件（缺内容与存储安全验收）。以上未采用，后续新增范围须新policy及重新确认。
- **影响**：增量认证head0005_shared_grants_t09、identity v2.t09与4新pathitems/5HTTP操作，原foundation/M0/旧迁移不变。Shared service独立同TX先UUID排序锁全部账户，actor绑定保持，不假造owner Principal；私有缓存和延迟readonly操作即时重验。最大30天仅为合成test scope策略，正式设置仍关闭；无新依赖，不实现真实worker、数据库immutable trigger/RLS或公众部署。
